# AstraForge Pixal3D/TRELLIS.2 на AMD через WSL2

Дата: 2026-11-02

## Цель

Добавить Pixal3D/TRELLIS.2 в существующий AMD-порт AstraForge для Radeon RX 9070 XT. Windows-редактор, Blender HIP, SDXL и Hunyuan3D должны продолжить работать без замены их ROCm-окружения. Результатом должна быть реальная генерация геометрии из изображения в GLB с возможностью открыть и показать результат пользователю.

## Выбранный подход

Pixal3D выполняется в отдельном Linux-окружении WSL2 с ROCm. Это выбрано вместо нативного Windows-порта, поскольку текущие Windows-колёса CuMesh, FlexGEMM, O-Voxel, FlashAttention и NATTEN собраны для CUDA и не загружаются в ROCm PyTorch. Linux позволяет собирать расширения из исходников и применять существующие ROCm-исправления.

Согласовано использование WSL2. WSL на компьютере отсутствует. Автоматическая перезагрузка запрещена: если она потребуется, работа приостанавливается с предупреждением пользователя.

## Архитектура

### Windows

Сохраняются текущие Node.js-сервер, редактор и основной ComfyUI на порту 8190. AstraForge использует существующий Pixal3D API и workflow без отдельной ветки генерации.

Добавляются AMD-компоненты установщика и адаптер запуска Pixal3D через WSL. Существующий NVIDIA-путь и его Windows-установщик не изменяются по назначению.

### WSL2

Отдельный дистрибутив содержит Ubuntu, Python, ROCm-совместимый PyTorch, ComfyUI, ComfyUI-Trellis2 и собранные из исходников расширения. ComfyUI слушает порт 8191 и доступен Windows-процессу через localhost.

VHDX дистрибутива, рабочие файлы и кэши размещаются внутри рабочей области проекта. Системные компоненты WSL устанавливаются только после согласования, уже полученного от пользователя.

### Модели и результаты

Веса Pixal3D, MoGe-2, NAF и DINOv3 сохраняются в постоянном каталоге проекта и не включаются в Git. Загрузки проверяются по размеру и доступным SHA-256, прерванная установка возобновляется без повторной загрузки целых файлов.

GLB возвращается через существующий HTTP API AstraForge, нормализуется и проходит текущую проверку геометрии. Проверочный PNG и GLB сохраняются в `data/runtime` для показа пользователю.

## Запуск и совместное использование GPU

Windows-адаптер запускает только принадлежащий проекту WSL-движок и повторно использует уже работающий совместимый сервер на порту 8191. Остановка AstraForge завершает принадлежащий проекту движок, но не удаляет дистрибутив и не затрагивает чужие WSL-дистрибутивы.

Существующий GPU mutex и механизм hand-over обязателен: Hunyuan3D и Pixal3D не выполняют генерацию одновременно. Перед запуском проверяются доступность RX 9070 XT, ROCm и свободная VRAM. Режим low-VRAM и последовательная выгрузка моделей используются для размещения в 16 ГБ.

## Обработка ошибок

- При отсутствии WSL выводится отдельная инструкция; установка больших моделей не начинается.
- Если требуется перезагрузка, выводится предупреждение; скрипт не перезагружает компьютер.
- CUDA-колёса не подменяются фиктивными DLL и не устанавливаются поверх ROCm.
- Отсутствие HIP-устройства, ошибка сборки расширения или неправильный GPU считаются ошибкой установки, а не успешным CPU fallback.
- Ошибки ROCm, нехватка VRAM и сбой отдельного расширения записываются в журнал с точным компонентом.
- Таймаут проверочного клиента не создаёт повторную генерацию: существующая задача возобновляется по идентификатору.

## Проверка

### Автоматические

- Тесты AMD-установщика: отдельные компоненты Pixal3D, сохранение флагов, отсутствие CUDA-индексов в AMD-профиле.
- Тесты Windows-адаптера: повторное использование сервера, корректные аргументы WSL, запрет остановки чужих дистрибутивов.
- Существующие тесты `npm test` и фокусный Blender HIP-тест проходят без регрессий.
- Изменённый AMD-патч не содержит моделей, кэшей, абсолютных пользовательских путей и локальных настроек.

### На реальном оборудовании

1. WSL2 видит AMD Radeon RX 9070 XT через ROCm.
2. CuMesh, FlexGEMM, O-Voxel и выбранный attention backend выполняют небольшие GPU-проверки.
3. ComfyUI-Trellis2 загружается без CUDA DLL и предоставляет все узлы существующего AstraForge workflow.
4. Одновидовая генерация создаёт непустой валидный GLB.
5. Четырёхвидовая генерация создаёт валидный GLB в пределах 16 ГБ VRAM; если аппаратное или upstream-ограничение делает это невозможным, результат явно фиксируется как ограничение, а не как полный успех.
6. Результат открывается в AstraForge и предоставляется пользователю для визуального просмотра.
7. После проверки все принадлежащие задаче серверы остановлены.

## Критерий готовности

Готовым этап считается после реальной одновидовой генерации Pixal3D на RX 9070 XT, получения валидного GLB в редакторе и предъявления результата пользователю. Поддержка четырёх видов проверяется отдельно и её статус указывается явно. Полный перенос не объявляется при наличии нерешённой ошибки расширения, CPU-only выполнения или отсутствии фактического результата.
